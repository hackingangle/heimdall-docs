# 彩虹桥多模态素材理解设计

- 日期：2026-07-26
- 状态：已确认，分阶段实施
- 产品目标：让用户添加任何常见素材后，都能直接进入阅读、搜索与创作流程；用户不需要理解解析器、OCR 或模型上下文限制。

## 1. 产品原则

1. **用户管理素材，系统管理表达**：一本书、一段访谈、一篇网页始终是一条素材；PDF、音频、字幕等只是原件或派生表达。
2. **创作结果仍然是素材**：延续现有 Material 单一内容实体，不新增独立 Generation 实体。
3. **保留原件，派生内容可重建**：原始文件不可丢失；解析文本、字幕、索引等均记录处理器与版本，可以重新生成。
4. **能力驱动，而非格式驱动**：界面关注“可阅读 / 可搜索 / 可创作”，不要求用户选择 PDF 解析器或 OCR 模型。
5. **渐进增强与可降级**：优先使用低成本原生解析，质量不足时再切 OCR/多模态；外部服务不可用时仍保留原件与失败原因。
6. **引用可回溯**：进入创作上下文的内容最终应能定位到页码、章节、时间码或来源 URL。

## 2. 统一领域模型

### Material

用户认知中的一个来源作品或创作结果。继续作为项目内唯一内容实体。

### MaterialAsset（第二阶段）

素材的原始载体或附件：

- `role`: original / attachment / cover
- `mime_type`, `file_name`, `file_key`, `size`, `checksum`

同一素材可同时拥有 PDF、封面、音频和字幕，不再通过不断扩充 `Material.type` 表达格式。

### MaterialRepresentation（第二阶段）

系统从原件生成的、可供人或模型消费的表达：

- `kind`: normalized_markdown / transcript / ocr_layout / table_json / vision_summary
- `status`: pending / processing / ready / partial / failed
- `content` 或 `storage_key`
- `processor`, `processor_version`, `quality_score`, `metadata`

### MaterialChunk（第三阶段）

长素材内部的检索单元，不出现在用户素材列表：

- `representation_id`, `content`
- `chapter_path`
- `page_start`, `page_end`
- `time_start`, `time_end`
- `embedding`

## 3. 标准处理流程

```text
添加素材
  → 保存原件
  → 识别 MIME 与基础元数据
  → 选择处理器
  → 生成规范表达
  → 质量检查与必要时降级
  → 建立分块索引
  → 计算素材能力
  → 进入创作上下文
```

处理器选择策略：

- 电子 PDF：原生文本抽取。
- 扫描 PDF：OCR。
- 复杂表格、公式与多栏排版：版面解析或多模态文件解析服务。
- 网页：正文提取 + 网页快照。
- 音频/视频：转写 + 时间码；视频按需补充关键帧。
- 图片：OCR、视觉描述或直接交给支持视觉输入的模型。

## 4. 创作上下文组装

Agent 不直接假定所有素材都是纯文本。Context Builder 根据任务、素材能力、模型能力和上下文预算选择表达：

- 短文本：全文。
- 长文档：检索相关分块并补充相邻上下文。
- 图片/图表：视觉模型原生输入，或使用视觉描述降级。
- 音视频：相关字幕段落 + 时间码 + 必要关键帧。
- 支持原生文件的模型：可直接传原件，但保留规范文本用于检索与跨模型降级。

生成结果应记录实际使用的素材、表达版本与引用锚点。

## 5. 网站体验

添加入口统一为“添加素材”，支持粘贴、上传和 URL。系统自动处理，素材列表展示能力状态：

- 原件已保存
- 解析中
- 可阅读
- 可搜索
- 可用于创作
- 处理失败或部分成功

素材详情提供“原件 / 解析内容”两个视图，并支持重新解析。创作选择器只允许选择真正具备可用表达的素材，同时说明会采用“全文”还是“相关片段”。

## 6. 分阶段交付

### 第一阶段：PDF 闭环（本次开始实施）

- 保持现有 Material 与文件 API 兼容。
- 增加独立 `extraction_status`，不再用生成状态表达文件解析。
- PDF 无文本内容时，上传后后台自动抽取并生成带页码的 Markdown。
- 解析器输出写入 `raw_content`，规范 Markdown 写入 `content`。
- 创作入口过滤未完成或失败的 PDF；服务端同时进行硬校验。
- 扫描件在第一版明确返回“需要 OCR”，不静默产生空素材。

### 第二阶段：表达层

- 引入 MaterialAsset 与 MaterialRepresentation。
- 接入 OCR/GLM 文件解析等可替换 Provider，并记录版本、成本与质量。
- 支持重新解析、部分成功和多表达切换。

### 第三阶段：长文档与多模态

- 引入 MaterialChunk 与检索索引。
- 建立 Context Builder，按任务和模型能力动态组装上下文。
- 支持网页、Office、音频、视频和图片。
- 生成内容带页码、章节、时间码等可回溯引用。

## 7. 第一阶段验收标准

1. 用户只上传电子 PDF，不粘贴文本，最终能够在解析视图看到正文并用于创作。
2. 解析中和失败状态在素材列表、详情与创作选择器中有明确反馈。
3. 扫描 PDF 不会被错误标记为“可用于创作”。
4. 用户已经手工提供的正文不会被自动解析覆盖。
5. 原件下载、PDF 阅读、手动文本素材和现有 AI 生成链路保持兼容。
