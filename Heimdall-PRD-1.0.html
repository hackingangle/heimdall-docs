1. 一句话

Heimdall 不是又一个聊天窗口。
它是创作者和多个 AI 共用的那张工作台：一期节目的资料、稿和录，都落在同一个地方。

名字取自北欧神话里彩虹桥的守望者。一边是做口播的人，一边是 Claude Code、Cursor、OpenClaw、Hermes 这些工具。 1.0 先把一座桥修通：人和多个 AI 读写同一期节目的同一份素材。

2. 为什么现在做

口播创作者已经在用 AI，但工作流是碎的：

环节今天代价
调研搜索、爬虫、网盘 PDF、各家对话各写各的下一期找不到，也无法引用
写稿再开一个对话，把资料粘进去上下文靠复制，人设每次重写
改稿备忘录 / Word不知道这稿用过哪些料
录制再抄进提词 App稿和镜头是两套工具
换模型换工具就换一套记忆AI 之间没有共享状态

1.0 不承诺「按一个按钮自动出片」。它先把更值钱的事情做对： 状态——一期节目只有一个项目，一份内容只存一次。

3. 给谁用

主用户 · 口播创作者

做知识、人物、讲史、讲经等中文长口播的个人或小团队。已经在用 AI 写稿，缺一个能把「资料 → 稿 → 录」收拢的地方。

次用户 · 外部 Agent

Claude Code、Cursor、OpenClaw、Hermes。凭一把 Token 把调研写进同一期，或把写稿人设读出去执行。

4. 1.0 已经跑通的主路径

验证场景：YouTube / 短视频口播。例如做一期「虚云老和尚」。

  1. 建第 N 期项目（期数、标题、栏目）。
  2. 资料进库：自己贴笔记；或让外部 Agent 按技能调研写入；书籍 PDF 上传后自动抽正文。
  3. 保存一个写稿 Agent（人设 + 自己的模型密钥，或平台默认模型）。
  4. 勾选年谱、开示录等素材，生成口播稿。稿本身还是一条素材，可以再改、再生成标题文案。
  5. 网页「录制模式」定速提词；或用 iPhone 跟读——说到哪，稿滚到哪。
  6. 导出 Markdown / 纯文本 / PDF，发到各平台。

5. 产品原则（已写进实现，不是墙上海报）

  • 创作结果即素材。手动、外部 AI、平台生成，三种来源一张表。没有另立「产物」「任务看板」。
  • 机制与策略分离。平台负责存、鉴权、调用模型、管文件；怎么调研、怎么拆大纲，由技能或用户的 Agent 决定。
  • 人和 AI 走同一扇门。网页登录，工具用 Token，打的是同一套项目 / 素材 / Agent 接口。
  • 先做一期节目。1.0 不内置自动调度引擎。人点，或外部 Agent 按技能执行。

7. 1.0 明确不做

避免讲成「全能自动出片」。

  • 不从「一个选题」无人值守跑完调研到发布
  • 不做平台内置的多 Agent 调度市场、任务 DAG
  • 不做剪辑时间线、自动烧字幕、广告分发
  • 不做扫描件 OCR、音视频精编
  • 不做团队空间（1.0 是单人工作台）
  • 网页不做跟读（跟读只在客户端）

8. 给投资人的讲解顺序（也是验收标准）

现场 8–10 分钟可以走完。闭环成立，即 1.0 产品成立。

  1. 打开 www.agoodbit.com，进入一期节目。
  2. 素材库：一条手写笔记 + 一份已抽出正文的 PDF。
  3. 智能体：展示一条写稿人设（提示词可见）。
  4. 勾选资料，生成一段口播稿；指出「稿还在素材库里，不是聊天气泡」。
  5. 网页打开录制模式，滚两段。
  6. 手机打开同一期，跟读几句，稿跟着走。
  7. 打开技能引导 / Token：说明 Claude 或 Cursor 可以把下一轮调研直接写回来。

9. 1.0 验证什么

在谈定价之前，先验证一件事：创作者是否愿意把一期节目的全部中间物放在 Heimdall， 而不是继续散落在聊天记录和网盘里。

下一阶段——更稳的跟读、更深的素材理解、轻量团队、按用量收费——只在这条工作流被用起来之后展开，不计入 1.0 验收。
