4. 分仓：实现要点

A. heimdall-backend PRIVATE

本地 server/ → https://github.com/hackingangle/heimdall-backend

控制平面。只做机制：鉴权、存数据、调 LLM、管文件。不内置调研/写稿策略，不内置 DAG。

分层（依赖单向 api → services → models）

app/
  main.py          装配 FastAPI、CORS、挂路由
  config.py        HEIMDALL_ 前缀
  db.py            engine / Session / get_db（DB 唯一入口）
  api/             薄路由：auth projects materials agents tokens llm_configs health debug
  services/        业务规则、生成、抽取、存储
  models/          User Project Material Agent LlmConfig ApiToken
  schemas/         对外契约
  core/            异常、错误体、JWT/Token 双鉴权、日志
alembic/           迁移
deploy/            仅给 CI 用
VERSION            整数，顶栏「后端 vM」

双鉴权

  • 同一 Authorization: Bearer …
  • hd_ 前缀 → ApiToken（库里 sha256）
  • 否则 → JWT（网页 / iOS 登录）
  • 实现：app/core/deps.py 的 get_current_actor / get_current_user
  • 素材 source：网页通道 manual，Token 通道 api，带 agent_id 创建则为 generated

关键路径

  • 创作：POST /api/projects/{id}/materials 带 agent_id → 立即 generating → BackgroundTasks → services/material.run_generation → services/llm.complete
  • PDF：PUT /api/materials/{id}/file → run_extraction（PyMuPDF）→ 写 raw_content/content
  • 存储：services/storage.py，HEIMDALL_STORAGE_BACKEND=local|oss，启动即校验 OSS 四项
  • 错误体统一 {"error":{"code","message"}}，service 抛 HeimdallError，不要 HTTPException

命令

cd server
make install && make migrate && make dev   # :8000
make check                                 # ruff + mypy --strict + pytest

AI 在本仓工作约定：server/CLAUDE.md（比根 README 新，以它和代码为准）。

B. heimdall-frontend PRIVATE

本地 web/ → https://github.com/hackingangle/heimdall-frontend

管理台。只消费 backend REST，不写业务库。构建时注入 VITE_API_BASE、APP_VERSION（来自 web/VERSION）。

分层（pages → hooks → api）

src/
  main.tsx         路由表
  App.tsx          顶栏：项目 / 智能体 / 技能引导
  api/             axios，禁止组件里散写请求
  hooks/           TanStack Query，缓存键 xxxKeys
  pages/           Projects / ProjectDetail / Agents / SkillsGuide / Login
  components/      纯 props（CreationPanel、TeleprompterView、MaterialViewDrawer…）
  types/           与后端 schema 对齐
  lib/             纯函数
VERSION            整数，顶栏「前端 vN」

路由

  • /login · /projects · /projects/:id · /projects/:id/materials/:materialId
  • /agents · /guide

实现注意

  • 生成中素材：useMaterials 见 generating 则 2s 轮询，不接 WebSocket
  • 网页提词是定速滚动，没有 ASR
  • 命令：npm run dev（5173）· npm run check · npm run build

约定：web/CLAUDE.md。

5. 发布：一仓一流水线

生产只许 GitHub Actions Deploy。禁止本机 deploy.sh / rsync / 手工 SSH 改线上代码。 Secrets 只存在各仓 Settings，不提交 production.env。
要更新什么推哪个仓的 mainworkflow线上结果
API / 迁移 / 主站 Nginx heimdall-backend CI 绿 → Deploy；或手动 Run curl https://www.agoodbit.com/health
网页 UI heimdall-frontend 同上 刷新 www.agoodbit.com
跟读转写 heimdall-asr 同上 curl -sf https://www.agoodbit.com/asr/health
iOS heimdall-client Xcode 归档，不走 ECS TestFlight / 真机
PRD / 交接 heimdall-docs push 即公开，无 Deploy 文档更新
技能安装脚本 heimdall-skills push 即公开，无 Deploy raw 脚本更新

首次上机顺序：backend → frontend → asr。ASR 假定机器上已有 heimdall 用户和主站证书。

Secrets 名称（值在 GitHub，本文不写）：

  • 三仓共用 SSH：DEPLOY_HOST DEPLOY_USER DEPLOY_SSH_KEY
  • backend：HEIMDALL_DATABASE_URL HEIMDALL_JWT_SECRET HEIMDALL_REGISTRATION_PASSPHRASE HEIMDALL_CORS_ORIGINS HEIMDALL_LLM_* HEIMDALL_OSS_*
  • frontend：VITE_API_BASE=https://www.agoodbit.com
  • asr：ASR_MODE NLS_APPKEY ALIYUN_AK_ID/SECRET ASR_PUBLIC_URL

细目以各仓 deploy/README.md 为准。

6. 版本号（跨仓约定）

顶栏 Tooltip：前端 vN · 后端 vM。

  • 改 web/ 行为 → 同一 commit web/VERSION +1
  • 改 server/ 行为 → 同一 commit server/VERSION +1
  • 两边都改 → 两个仓各 +1、各提交（它们是两个 git）
  • 只改文档 / Cursor 规则、行为不变 → 不 bump
  • 只能是递增整数，禁止 semver
